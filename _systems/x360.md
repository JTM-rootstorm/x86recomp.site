The Xbox 360's Xenon runs 64-bit PowerPC code in 32-bit mode, so
x86recomp grows a PowerPC core: a lifter (`recomp_lift_ppc`) and the CPU
model its lifted code runs on, over a big-endian 4 GiB guest arena. The
**Xbox 360** platform module sits on that core as Orbis and Horizon sit
on theirs, and shares the same host layer; a 360 title builds without
the x86 path.

The module is developed on x86recomp's
[`{{ page.branch }}` branch]({{ site.repo }}/tree/{{ page.branch }})
until it is merged into main; its
[commits]({{ site.repo }}/commits/{{ page.branch }}) are the progress
log.

## Status

- **XEX2 reader**: stored, basic and LZX-compressed images (with an LZX
  decoder of its own), PE sections, `.pdata`, import thunks and exports
  by ordinal. An owner's encrypted XEX is decrypted first with their own
  key file, which is never part of any repository.
- **Integer core**: fixed-point, branch, condition register, storage
  control and special-purpose register instructions, with function
  discovery and jump tables.
- **Floating point**, exact: SoftFloat under FPSCR with the PowerPC's own
  NaN and rounding rules and every FPSCR effect.
- **VMX**: the 128-bit vector registers and VSCR, every VA, VX and VC
  form, and the Xenon's LVLX loads.
- **Oracle**: QEMU's PowerPC 970 in 32-bit mode. A fixture built from
  source must print the same lifted, every instruction form is checked
  bit for bit from random states, and planted bugs in the lifted
  semantics must be caught.
